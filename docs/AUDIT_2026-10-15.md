## How this audit was made

- **Lead pass.** A Traceworks Cartographer scan for the map, six read-only
  review lanes (jobs, auth, storage, fetchers, AI/exports, frontend) whose

  the same validation, one live call per source ("heart disease", two

  instance (topic "school start times", test admin `grokaudit`). Every
  finding that only this pass made was then checked by the lead against
  the source, and Europe PMC live.

Each finding says who found it (**lead**, **second**, **both**) and how it
was confirmed: **live** (request, log or browser) or **read** (source
only). No production data was changed. Validation at the time: `ruff
check .` clean, `pyright app` 0 errors (6 optional-import warnings), 1048

## 16. Admin console

- **16.1 Saving a banner draft takes the live banner down.** Fixed in #93. Both, live.
  `upsert_banner` loads the newest row (`ORDER BY updated_at DESC LIMIT 1`)
  and updates it, published or not (`app/storage/helpdesk.py:611-627`,
  `767-773`); Save draft always posts `status: 'draft'`
  (`static/js/admin.js:973-992`). Publish, then Save draft with new text:
  the status becomes `draft` and students no longer see the banner. The
  dialog says "Saves the text without showing it to anyone."
- **16.2 The publish word can be skipped.** Fixed in #93. Lead, live. `POST
  /api/admin/banner` with `status: "published"` returned 200 and published
  without the `publish` word (`app/routes/admin.py:1359-1366`). The
  activity feed then reads "saved a banner draft (published)". Found
  while fixing it: Roll back restored the revision's status as well, so
  rolling back to a published revision republished without the word
  (`rollback_banner`).
- **16.3 An admin can act on their own account.** Fixed in #93. Lead, live. Disabling
  the test admin returned 200; every following request, including
  re-enable, was 401. With one admin this needs a database edit.
  `_begin_action` never compares the target with the acting admin, and
  the JS has no guard. Revoke-sessions works the same way. Set-email has
  no target rule either, so a stolen admin session can set its own
  recovery address, reset the password and pass `/api/ops/reauth`
  (`app/routes/admin.py:156-173`).
- **16.4 Logout keeps the support view.** Fixed in #93. Both; lead live. `/logout`
  deletes `access_token` and `csrf_token` but not `support_view`
  (`app/routes/auth.py:538-546`), and `current_user` honours the view
  before the JWT (`app/core.py:607-620`, `666-694`). After logout,
  `/api/libraries` and `/api/account/look` still answered 200 as the
  student. Exit then lands on `/admin` with no admin session.
- **16.5 A support view re-checks neither side.** Fixed in #93. Lead (admin), second
  (student), read. `_support_view_user` (`app/core.py:666-694`) and
  `get_support_view_by_token` (`app/storage/helpdesk.py:248-279`) check
  only `ended_at` and `expires_at`. They ignore whether the admin is still
  an admin and enabled, and whether the student is disabled, locked or
  has had sessions revoked (`token_version`). The JWT path checks these
  (`app/core.py:630-634`). Decision while fixing: the view is tied to the
  admin's own session, which covers logout, a revoked or disabled admin and
  lost admin rights. The student-side checks were left out on purpose: a
  helpdesk view of a locked or disabled student is the normal way to help
  them, and the view is the admin's session, not the student's.
- **16.6 The Host tab reports a sleeping Laya as down.** Fixed in #93. Both, live.
  `_laya_status` probes `/health` with a 1.5 s timeout and no `wake()`
  (`app/routes/admin.py:445-461`); a socket-activated worker needs about
  8 s to load (`app/services/laya_client.py:23-29`, `WAKE_TIMEOUT` 15 s).
  Observed "not answering" while idle, "up, model loaded" after a topic
  request.
- **16.7 The watchdog time is a raw epoch.** Fixed in #93. Both, live. "WATCHDOG OK ·
  1792099144.5624652"; `_watchdog_status` passes `checked_at` through
  (`app/routes/admin.py:418-431`, `static/js/admin.js:266`).
- **16.8 Activity feed wording.** Fixed in #93. Lead, live. When actor and account are
  the same the line ends in a dangling preposition ("demoadmin left a note
  on", "audit1015 replied to a ticket for"). `support-view-end` and
  `export-packet` have no wording entry. Student ticket actions appear
  under "Recent admin activity".
- **16.9 Smaller.** Fixed in #93; the Overview counts in its last two sentences in #100. Lead, read. Unlock, Re-enable and Retry prepare are
  enabled in every state (only the job buttons follow `can_*`). Retry
  fetch sends `user@example.com` as the contact address
  (`app/routes/admin.py:1103`). Overview "Stuck jobs" and source errors
  come from the capped in-memory job map. The ticket badge comes from the
  25-row list on the Tickets tab but from the real count on Overview.

## 17. Account safety

- **17.1 Lockout never resets, and a lock ends live sessions.** Fixed in #94. Lead,
  read. `record_login_failure` adds to `failed_logins` and never resets it
  when `locked_until` has passed (`app/storage/user_db.py:711-738`), so
  after the first lock one wrong password relocks for 15 minutes.
  Anyone can keep any account locked. `current_user` returns None for a
  locked account (`app/core.py:633`), so eight wrong passwords against the
  admin's name also sign the admin out of `/admin` and `/ops`. The second
  pass marked the lockout sound; it tested only the first lock.
- **17.2 The rate limiter trusts any signed JWT.** Fixed in #94. Lead, read.
  `rate_limit_key` uses `get_current_user`, which checks signature and
  expiry only (`app/core.py:107-117`, `app/auth.py:223-228`). Guest tokens
  live 30 days while the guest account is purged at 30 minutes, so
  `/guest` hands out unlimited fresh per-user buckets for `/login`,
  `/reset-password/request`, `/register` and `/api/ai/*`.
- **17.3 Password re-auth is unthrottled and unlogged.** Fixed in #94. Both, read. The
  admin view, ops re-auth, change-password and delete-account checks never
  count failures or write auth events. Change-password and delete-account
  have no `@limiter.limit` (`app/routes/auth.py:549-554`).
- **17.4 Login and register skip CSRF.** Fixed in #94. Second, read. Neither POST checks
  the double-submit token (`app/routes/auth.py:98-105`, `334-341`); every
  later account POST does. Login CSRF signs a victim into an account the
  attacker chose; `_safe_next_url` still limits the redirect.
- **17.5 A guest cannot reach the register form.** Fixed in #94. Second, live. `GET
  /register` redirects any signed-in session, guests included, to
  `/search` (`app/routes/auth.py:205-209`). The guest banner's "Create a
  free account" (`templates/base.html:36`) bounces; the guest must end the
  demo first.
- **17.6 Admin handles are not reserved.** Fixed in #94. Lead, read. Registration
  reserves only `guest_*` (`app/auth.py:84-87`). A name listed in
  `ADMIN_USERNAMES` that has no account yet can be registered by anyone,
  who is then an admin.
- **17.7 Login timing reveals which handles exist.** Fixed in #94. Second, read. An
  unknown username skips bcrypt (`app/routes/auth.py:107-108`).
- **17.8 Reset codes show whenever `DEBUG` is on.** Fixed in #94. Second, read.
  `_reset_codes_in_response` returns true for `DEBUG` as well as
  `RESET_CODES_IN_RESPONSE` (`app/routes/auth.py:223-227`). Production has
  `DEBUG=false`.
- **17.9 Ops re-auth falls back to a known secret.** Fixed in #94. Second, read. With
  an empty `SECRET_KEY` the secret is `ops-dev-only`
  (`app/routes/ops.py:59-61`). Production is not affected: the app refuses
  to start without a key unless `DEBUG` is on.
- **17.10 Fetch preferences are shared by every account in a browser.** Fixed in #94.
  Second, live. One `localStorage` key, `lra_fetch_prefs_v1`
  (`static/js/common.js:25`), holds topic, sources, count, mode and the
  contact email (`static/js/collect.js:523-546`, `570-581`). Logout does
  not clear it. A new account opened with the previous student's topic
  and areas.
- **17.11 Support view responses lack security headers.** Fixed in #94. Lead, read.
  `SupportViewMiddleware` is added after `SecurityHeadersMiddleware`, so
  its own 403 and 302 responses carry no CSP.
- **17.12 The Ship validate gate is a global flag.** Fixed in #94. Lead, read.
  `last_validate_ok` is not tied to the staging SHA, and `ask_grok` edits
  do not reset it.

## 19. Search page and ranking

- **19.1 The score shown does not match the order.** Fixed in #96. Both, live. Hybrid
  rank min-max normalises TF-IDF over the shortlist, then blends `0.7 *
  semantic + 0.3 * lexical`, and stores the raw semantic score as
  `similarity_score` (`app/services/pipeline.py:664-678`). The paper with
  the most word overlap gets lexical 1.0 however small the overlap: on the
  demo corpus "Public comment periods and environmental justice concerns"
  (semantic 0.087) ranked 4th for an exercise and depression question.
  Under "Sort: Similarity" the cards read 0.321, 0.354, 0.167, 0.302;
  on the school-start search 0.830 sat above 0.833. Exact-word boost is
  on by default (`static/js/search.js:10`); `clientSort` does not reorder
  for Similarity (`search.js:1154-1163`, `1353-1359`); the tooltip says a
  higher number is a stronger match. `pico_boost` then re-sorts by raw
  semantic score and discards the blend (`app/services/enrich.py:50`).
- **19.2 The rail goes stale.** Fixed in #96. Lead, live. `fillSimpleRailStats` runs
  only from `loadSearchEmptyState` and one tools path
  (`static/js/search.js:455-510`, `simple_tools.js:1035`). After Not
  relevant the rail still said Kept 28, Removed 0; after a reload, 27
  and 1.
- **19.3 Duplicates are resolved silently after prepare.** Fixed in #96. Lead, live.
  `static/js/collect.js:1585-1592` posts `/api/resolve-duplicates` with no
  preview or undo. `spec.md` says duplicate exclusions preview before
  apply. It is also why Narrow it down says "about 49 of 196" above "197
  papers ready".
- **19.4 The layout notice shows for every new browser.** Fixed in #97. Lead, live.
  Shown unless `localStorage.uiMode === 'simple'`
  (`static/js/common.js:1641-1667`), pinned by
  `tests/test_one_flow_browser_state.py:22`. `spec.md` says only old mode

- **19.5 Narrow it down sends six ranking requests per question.** Fixed in #97. Lead,

- **19.6 Laya topic areas stop following the topic.** Fixed in #97. Lead, live. The
